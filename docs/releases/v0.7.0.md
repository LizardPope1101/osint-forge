# OSINT Forge v0.7.0

OSINT Forge v0.7.0 combines the v0.6 investigation-planning foundation with
the v0.7 evidence-integrity and portability layer. A case can now resolve and
preserve an explainable workflow plan, bind derived entities to hashed source
artifacts, verify material case files, and move a full case safely between
systems.

## Highlights

- Versioned, deterministic investigation workflows and `osint case plan`.
- Explainable plugin selection, rejection, coverage gaps, stage purpose, and
  expected information gain.
- Ordered workflow execution with bounded concurrency, dependencies, timeouts,
  cancellation, and resume behavior.
- SHA-256 integrity manifests that detect missing, modified, and unexpected
  case artifacts.
- Deterministic full-fidelity bundles with independent inspection, safe import,
  and lossless case round trips.
- Conservative redacted bundles that exclude raw evidence, targets, commands,
  authorization details, paths, and analyst notes.
- Hash-bound entity provenance ready for the later correlation layer.
- Fail-closed protections against traversal, links, special files, duplicate
  members, corruption, schema mismatches, unsafe overwrites, and redaction
  leaks.

## Important boundaries

Integrity verification establishes that covered bytes match a recorded
manifest. It does not establish authorship, source truth, forensic
certification, or legal chain of custody. Redacted bundles are inspection-only
and cannot be imported as full cases.

This release does not yet implement identity correlation, confidence scoring,
search-provider discovery, or recursive lead enumeration. Those capabilities
remain post-v0.7 roadmap work built on the planning and evidence contracts
stabilized here.

## Upgrade

Update a checkout to the `v0.7.0` tag and run:

```bash
sudo ./scripts/install-framework.sh
osint --version
osint forge validate
```

Existing case data is preserved. Back up important case directories before any
upgrade and retain the original evidence when exchanging case bundles.

## Validation status

The development candidate passed the 15-step development harness, 106 Python
tests with three environment-dependent skips, plugin and workflow validation,
CLI checks, shell syntax checks, and ShellCheck on Debian. Final release QA,
tagging, publication, and administrative closeout remain separate required
gates.
